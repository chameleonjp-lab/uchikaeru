# うちかえる

「うちかえる」は、迫るカエルの大群を拠点の自動攻撃で撃退し、ランダムに提示される武器・強化カードを選びながら 60 波クリアを目指すスマホ向けブラウザ防衛ゲームです。

公開 URL: https://chameleonjp.codeberg.page/uchikaeru/

## 現在の正仕様

- `index.html` 1 ファイル構成で、ビルド工程や複数ファイル化は行いません。
- `game_slug` は `uchikaeru`、公開 URL は `https://chameleonjp.codeberg.page/uchikaeru/` です。
- ランキング基数は `RANK_BASE = 2000000` です。送信値は `rankingScore = clearWave * 2000000 + min(1999999, detailScore)` で計算します。
- `detailScore` はゲーム中の `battleScore` に残り拠点 HP ボーナスと 60 波クリアボーナスを足した補助点です。ランキング送信時だけ最大 `1,999,999` に丸め、結果画面の自分の表示は丸め前の実 `detailScore` を優先します。
- カエルの実体力は `FROG_HP_MULTIPLIER = 3.5` を現在値とします。過去調整案では 5 倍の記述がありましたが、現行コードでは 3.5 を採用しています。
- 支援・強化系は通常武器候補から除外し、武器枠を消費しない強化カードとして扱います。強化カードは `selectedWeapons` に入れず、拠点修理、全体火力強化、攻撃速度強化、敵の移動低下の各効果だけを反映します。
- 罠系は攻撃・罠武器として武器枠を消費しますが、通常弾は撃たず、防衛ライン付近に罠を設置して敵にダメージや遅延を与えます。
- 結果画面では自動で 1 回だけ `submit_score` を呼び、ランキング TOP10 と「ホームに戻る」を表示します。ランキング登録ボタンは追加しません。
- リタイア時も `submit_score` を呼び、0 波リタイアでも `play_count` に計測される仕様です。
- Supabase は Publishable key のみを使い、service_role key や `public.scores` は使いません。送信 RPC は `submit_score`、ランキング取得 RPC は `get_best_score_ranking` です。

## リポジトリ構成

- `index.html`: HTML / CSS / JavaScript を同梱したゲーム本体。ビルドなしでそのまま配信します。
- `README.md`: 仕様、ランキング連携、修正履歴を記録するドキュメントです。

npm、Vite、外部ビルド、複数ファイル化は使わず、`index.html` 1 ファイル構成を維持します。

## ゲーム仕様

- ゲーム名: うちかえる
- `game_slug`: `uchikaeru`
- テーマ: 画面上側から迫るカエルの大群を、画面下側の拠点から自動攻撃で撃退します。
- 目標: 全 60 波クリア。
- 武器: 攻撃・罠武器 7 カテゴリ × 5 種類を通常候補に出します。支援・強化系 5 種類は内部データに残っていますが、通常武器候補からは除外します。
- カード選択: 各波クリア後に 3 枚の候補から 1 つ選択します。攻撃・罠武器の追加/強化、または武器枠を消費しない強化カードが提示されます。
- 初回武器: 名前入力後の 3、2、1 カウントダウン後、1 波目の前に罠系も除外した攻撃可能な通常弾系武器だけを 3 枚提示し、1 つ選んでから 1 波を開始します。
- 敗北条件: 拠点体力が 0 になると結果画面へ進みます。
- リタイア: プレイ中にリタイアした場合も、クリア済み波数とスコアで結果を確定します。
- 性能上限: 敵 80 体、弾 120 発、エフェクト 120 個。攻撃・罠武器の最大枠は 6 個です。

## ランキング仕様

ランキングは Supabase の共通 RPC を使うベストスコア型・降順です。結果画面にランキング登録ボタンは置かず、RESULT 確定後に自動で 1 回だけ送信します。

送信値は波数を最優先するため、次の整数を使います。

```text
rankingScore = clearWave * 2000000 + min(1999999, detailScore)
```

`RANK_BASE = 2,000,000` です。60 波クリア時の最大送信値は `60 * 2,000,000 + 1,999,999 = 121,999,999` です。`122,000,000` は 61 波クリア / 0 点相当になるため仕様外です。ゲーム本体は RESULT 確定時と送信直前の両方で上限をかけ、`122,000,000` 以上の score を送らないようにします。送信直前の `p_score` は 0 以上の PostgreSQL `integer` 範囲内にも正規化します。

画面表示は次の形式です。

```text
○波クリア / ○○点
```

結果画面の自分の表示は、保存用 `rankingScore` ではなく丸め前の実 `detailScore` を優先します。ランキング TOP10 は保存済み score を `RANK_BASE = 2,000,000` で分解表示します。たとえば、59 波クリアで `detailScore = 1,070,642` の場合は `rankingScore = 119,070,642`、表示は `59波クリア / 1,070,642点` です。60 波クリアで `detailScore = 2,037,256` の場合、送信用の `detailScore` は `1,999,999` に丸め、`rankingScore = 121,999,999`、ランキング表示は `60波クリア / 1,999,999点` です。リタイア時も `submit_score` を呼び、0 波リタイアでも `0波クリア / 0点` として送信して `play_count` に計測します。

## Supabase 連携仕様

- Supabase URL: `https://mlpnjgezrnhdxsxolyzj.supabase.co`
- 使用キー: Publishable key のみ。
- secret key / service_role key は使用しません。
- `public.scores` は使用しません。
- 送信 RPC: `submit_score`
- ランキング取得 RPC: `get_best_score_ranking`
- 共通仕様上の関連 RPC: `get_first_try_ranking`, `get_game_play_stats`

スコア送信では、`p_display_name`, `p_game_slug`, `p_score`, `p_client_version` を渡します。ランキング取得では `p_game_slug` と `p_limit` を渡します。送信や取得に失敗しても結果画面とシェア機能は壊さず、無限再送もしません。結果画面にはベストランキング上位 10 件を表示し、取得できない場合はエラーメッセージ、0 件の場合は未記録メッセージを表示します。

## 今回の修正内容

- ランキング内部スコアの基数を `RANK_BASE = 2,000,000` に変更しました。
- `rankingScore = clearWave * 2,000,000 + min(1,999,999, detailScore)` とし、RESULT 確定時と送信直前に最大 `121,999,999` へ丸めることで、`122,000,000` 以上をゲーム本体から送らないようにしました。
- 結果画面の自分のスコアは丸め前の実 `detailScore` を優先し、ランキング TOP10 は保存済み score を `2,000,000` 基準で分解表示します。
- 未使用の旧スコア計算関数 `calculateDetailScoreOld()` を削除し、将来修正で古い計算方式を誤参照しないようにしました。
- 貫通弾に命中済み敵の集合を持たせ、同一敵への連続多段ヒットを防ぎつつ複数敵への貫通は維持しました。
- スロウ合計が 100% を超えても速度倍率を最低 10% に下限固定し、敵の逆走を防ぎました。
- DOT 付与時に弾ダメージ由来の `dotDamage` を敵へ保持し、武器レベル上昇が継続ダメージにも反映されるようにしました。
- 全体火力、攻撃速度、全体スロウに上限を設定し、グローバル強化が青天井にならないようにしました。
- ジャンプ敵は座標を瞬間加算せず、短時間の速度倍率上昇で「急に詰める」挙動を表すようにしました。
- 拠点ダメージに短いクールダウンを設け、複数敵の同時侵入による理不尽な瞬間多段ダメージを抑制しました。
- 初回候補から罠系も除外し、「最初の攻撃武器を1つ」という表示と実際の候補を一致させました。通常の波クリア後カードでは罠系を引き続き候補に出します。
- 武器チップの枠色と薄い背景色をカテゴリ色に合わせ、支援系非武器化と罠系の罠設置方針は維持しています。
- 最終改善フェーズでは、0 波リタイア時の `detailScore` を 0 にし、`0波クリア / 0点` として送信するようにしました。
- 範囲攻撃と連鎖攻撃は対象を先に配列化してからダメージを与え、敵配列削除による判定抜けを防ぎました。
- DOT で倒れた敵が、その後の移動や拠点到達判定を続けないようにしました。
- 罠は 7 レーンの敵動線上に設置されやすくし、発動時に周囲へスプラッシュダメージを与えるようにしました。
- 上限到達済みの強化カードは候補に出にくくしました。
- DOT 中の敵や十分スロウ済みの敵を、同系統武器が狙い続けにくくしました。
- 攻撃クールダウンは超過時間をある程度持ち越し、通常弾の最小間隔はまず 140ms としました。
- 55 波以降は敵 HP 倍率と編成を強化し、終盤サバイバルボーナスを 1 波あたり 6,000 点追加しました。
- 終盤サバイバルボーナスは Gemini 案の 15,000 点ではなく 6,000 点に抑え、固定系スコアが約 60 万点付近に収まるよう調整しました。
- 維持した仕様: `index.html` 1 ファイル構成、ゲーム名「うちかえる」、`game_slug=uchikaeru`、公開 URL、60 波クリア目標、3 枚候補、敵 80 体・弾 120 発・エフェクト 120 個上限、RESULT 後のランキング自動 1 回送信、ランキング登録ボタンなし、リタイア時の送信、`submit_score` / `get_best_score_ranking`、Publishable key のみ、`public.scores` 不使用、支援・強化系が武器枠を消費しない方針。

- 最終表示・カード候補・罠配置の改善として、全体火力、攻撃速度、敵の移動低下は 1 回以上取得後に下部チップへ Lv 表示されます。
- 全体強化は上限付きで、従来どおり `selectedWeapons` には入らず武器枠を消費しません。
- 上限到達済みカードは候補に出さず、候補不足時は必ずスコア獲得効果がある「補給整備」を出します。
- 罠は敵の進路上に置かれやすくし、配置範囲を少し上へ移動しました。

## 動作確認観点

- ホーム、ルール、名前入力、カウントダウン、初回武器選択、プレイ、波クリア後カード選択、結果画面へ進めること。
- 名前未入力では開始できないこと。
- 候補選択中と RESULT 後に敵・弾・当たり判定・スコア加算が止まること。
- `requestAnimationFrame` が二重起動せず、ループが止まらないこと。
- iPhone SE 幅で横スクロールせず、Canvas とカードが重ならず、下部ボタンが押せること。
- ランキング表示が `○波クリア / ○○点` 形式になること。
- 支援・強化系が通常武器候補に出ず、選んでも武器枠を消費しないこと。
- 罠系カードに、弾ではなく罠を設置する説明が表示されること。
- 60 波クリアで補助点が `1,999,999` に丸められ、送信値が `121,999,999` を超えない仕様と README が矛盾しないこと。
