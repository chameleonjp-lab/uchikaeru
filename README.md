# うちかえる

「うちかえる」は、迫るカエルの大群を拠点の自動攻撃で撃退し、ランダムに提示される武器・強化カードを選びながら 60 波クリアを目指すスマホ向けブラウザ防衛ゲームです。

公開 URL: https://chameleonjp.codeberg.page/uchikaeru/

## リポジトリ構成

- `index.html`: HTML / CSS / JavaScript を同梱したゲーム本体。ビルドなしでそのまま配信します。
- `README.md`: 仕様、ランキング連携、修正履歴を記録するドキュメントです。

npm、Vite、外部ビルド、複数ファイル化は使わず、`index.html` 1 ファイル構成を維持します。

## ゲーム仕様

- ゲーム名: うちかえる
- `game_slug`: `uchikaeru`
- テーマ: 画面上側から迫るカエルの大群を、画面下側の拠点から自動攻撃で撃退します。
- 目標: 全 60 波クリア。
- 武器: 8 カテゴリ × 5 種類の合計 40 種類。
- カード選択: 各波クリア後に 3 枚の候補から 1 つ選択します。
- 初回武器: 名前入力後の 3、2、1 カウントダウン後、1 波目の前に攻撃可能な武器だけを 3 枚提示し、1 つ選んでから 1 波を開始します。
- 敗北条件: 拠点体力が 0 になると結果画面へ進みます。
- リタイア: プレイ中にリタイアした場合も、クリア済み波数とスコアで結果を確定します。
- 性能上限: 敵 80 体、弾 120 発、エフェクト 120 個。

## ランキング仕様

ランキングは Supabase の共通 RPC を使うベストスコア型・降順です。結果画面にランキング登録ボタンは置かず、RESULT 確定後に自動で 1 回だけ送信します。

送信値は波数を最優先するため、次の整数を使います。

```text
rankingScore = clearWave * 10000000 + min(9999999, battleScore)
```

Supabase `game_scores` の `integer` 上限に収めるため、内部基数は `10000000` です。`battleScore` は `RANK_BASE - 1` 以下に丸め、60 波クリア時でも `609999999` 以下になるようにします。画面表示やシェア文では巨大な送信値をそのまま出さず、必ず次の形式に分解します。

```text
○波クリア / ○○点
```

0 波クリア、敗北、リタイア、60 波クリアのいずれでも同じ形式で表示します。リタイア時も `submit_score` を呼び、0 波リタイアでも `0波クリア / 0点` として送信して `play_count` に計測します。

## Supabase 連携仕様

- Supabase URL: `https://mlpnjgezrnhdxsxolyzj.supabase.co`
- 使用キー: Publishable key のみ。
- secret key / service_role key は使用しません。
- `public.scores` は使用しません。
- 送信 RPC: `submit_score`
- ランキング取得 RPC: `get_best_score_ranking`
- 共通仕様上の関連 RPC: `get_first_try_ranking`, `get_game_play_stats`

スコア送信では、`p_display_name`, `p_game_slug`, `p_score`, `p_client_version` を渡します。ランキング取得では `p_game_slug` と `p_limit` を渡します。送信や取得に失敗しても結果画面とシェア機能は壊さず、無限再送もしません。結果画面にはベストランキング上位 10 件を表示し、取得できない場合はエラーメッセージ、0 件の場合は未記録メッセージを表示します。

## 今回の修正内容

- Supabase `game_scores` の integer 上限に収めるため、ランキング内部スコアの基数を `100000000` から `10000000` に変更しました。
- `battleScore` は `RANK_BASE - 1` 以下に丸め、60 波クリア時でも integer 上限を超えないようにしました。
- 結果画面にホームへ戻るボタンを追加しました。
- 結果画面にベストランキング上位 10 件を表示するエリアを追加しました。
- リタイア時も `submit_score` を呼び、プレイ回数に計測されるようにしました。
- ランキング送信・取得に失敗しても、結果画面とシェア機能は壊さないようにしました。

- カエルの実体力を `FROG_HP_MULTIPLIER = 5` で 5 倍にしました。`ENEMY_DEFS` の個別 HP、score、damage、speed、ランキング仕様、拠点体力、武器火力、敵 80 体・弾 120 発・エフェクト 120 個上限は維持しています。
- `.screen` と `.game-wrap` の表示制御を整理し、`HOME` / `RULE` / `NAME` / `READY` / `PLAYING` / `CHOOSING` / `RESULT` / `ERROR` のうち 1 画面だけが active になるようにしました。`RESULT` 遷移時はスクロール位置も先頭に戻します。
- `.app` と `#game` を `100dvh` 内に収め、HUD、Canvas、状態表示、武器チップ、カード候補がスマホ 1 画面内で収まるように高さ設計を見直しました。カード選択欄は内部スクロールにし、結果画面がゲーム画面下に続かない構成です。
- 攻撃起点を画面中央下の 1 点から、拠点周辺に並ぶ最大 6 個の武器スロットへ変更しました。Canvas 上に台座、絵文字、Lv を描画し、弾は各武器スロットから発射されます。
- 敵の出現を横一列・斜め列・左右 2 列・ボス護衛の小隊フォーメーションに変更しました。31 波以降は同時出現数、45 波以降は後続の見え方、55 波以降はボス＋雑魚小隊の同時圧が強くなるように調整しました。
- 武器カテゴリごとに狙いを分け、連射は近距離、貫通は同レーン奥、範囲爆発と連鎖は密集、遅延は速い敵や前線、継続ダメージは高 HP を優先しつつ、同じ 1 体へ集中しすぎないよう既存弾のターゲットを加味します。
- 罠系は通常弾ではなく、防衛ライン付近に最大 20 個まで設置され、近づいた敵にダメージと遅延を与える簡易設置型に変更しました。
- 敵本体は常にカエル絵文字として描画し、遅延や継続ダメージは輪・色・短いエフェクトで表すようにしました。範囲、連鎖、罠、支援もカテゴリごとに最低限違うエフェクトを出します。
- 下部の武器チップは長い武器名ではなく `絵文字 Lv` 表示にして、スマホ幅でも現在の構成を読みやすくしました。
- 60 波クリア、拠点突破、リタイアの直前に状態文を更新し、結果画面へ移る前の状態と結果が矛盾しにくいようにしました。
- `DEBUG=true` のときだけ、ランキング送信失敗時に RPC 名、HTTP ステータス、エラー本文先頭、`game_slug`、送信 score、名前有無を console と debug 表示に出すようにしました。`DEBUG=false` では従来通り短いユーザー向け文言だけです。
- 維持した仕様: `index.html` 1 ファイル構成、ゲーム名「うちかえる」、`game_slug=uchikaeru`、公開 URL、60 波クリア目標、40 武器、3 枚候補、敵 80 体・弾 120 発・エフェクト 120 個上限、RESULT 後のランキング自動 1 回送信、ランキング登録ボタンなし、`submit_score` / `get_best_score_ranking`、`rankingScore = clearWave * 10000000 + min(9999999, battleScore)`、Publishable key のみ、`public.scores` 不使用。

- 拠点ダメージ判定ラインを、画面に見えている赤い防衛ラインと同じ `layout.defenseLineY` に統一しました。
- 拠点ダメージ文字は赤い線のすぐ上に出るよう修正しました。

- 武器スロットの基準を防衛ライン基準から城基準へ変更し、発射地点が上に離れすぎる問題を修正しました。
- `getWeaponSlotPosition()` を扇形の大きな上方向配置から、城の近くに並べる固定オフセット方式へ変更しました。
