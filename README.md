# うちかえる 開発手順計画書

## 固定方針

- ゲーム名は「うちかえる」、`game_slug` は `uchikaeru`、公開予定 URL は `https://chameleonjp.codeberg.page/uchikaeru/` とする。
- 実装は `index.html` 1ファイルで完結させ、外部ビルド・npm・サーバー処理は使わない。
- ゲームはスマホ向けブラウザゲームとし、iPhone SE 幅でも横スクロールなしで遊べることを必須にする。
- 迫ってくるカエルの大群を画面下側の拠点から自動攻撃で撃退し、波ごとにランダム武器・強化カードを1つ選ぶ。
- 最終目標は60波クリア。敗北・リタイア時は到達波ではなくクリア済み波数を結果に表示する。
- ランキングはベストスコア型・降順。終了時に自動で1回だけ送信し、ランキング登録ボタンは置かない。
- `public.scores` は使わず、既存共通RPC形式に寄せた送信・取得関数に閉じ込める。
- Supabase の secret key / service_role key は絶対に書かない。

## 実装前確認

- 現在のリポジトリには `.gitkeep` のみがあり、既存の `README.md`、`index.html`、ランキング設定ファイルは存在しない。
- そのため、まず本計画書を `README.md` として固定し、その後 `index.html` を新規作成する。
- 既存ゲームの共通RPC実装はこの作業環境内では確認できないため、ランキング連携は `submit_game_score` / `get_game_ranking` など複数候補を試すフォールバック関数として実装する。

## 実装順序

1. `README.md` に固定仕様・性能予算・実装手順を整理する。
2. `index.html` に HTML / CSS / JavaScript を同梱する。
3. 画面状態 `HOME / RULE / NAME / READY / PLAYING / CHOOSING / PAUSED / RESULT / ERROR` を定義する。
4. Canvas で敵・弾・拠点・エフェクトを描画し、HTML はメニュー、カード、結果、ランキングに限定する。
5. 60波の生成、敵種、スコア、武器40種、カード候補3枚、最大所持武器6種を実装する。
6. 敵80体、弾120発、エフェクト120個の上限を実装し、RESULT後は更新を止める。
7. ランキング送信値 `ranking_score = clear_wave * 100000000 + battle_score` を実装し、表示時は波数と点に分解する。
8. Web Share API と Clipboard のフォールバックを実装する。
9. 静的確認と可能な範囲の動作確認を行う。

## 実装後確認項目

- 60波クリアと敗北・リタイア結果が正しいこと。
- ランキング送信が RESULT 確定後1回だけであること。
- ランキング表示で `ranking_score` をそのまま出さず、「○波クリア / ○○点」に分解すること。
- iPhone SE 幅でカードとCanvasが重ならず、横スクロールしないこと。
- `DEBUG = false` で公開時のデバッグ表示が隠れること。
